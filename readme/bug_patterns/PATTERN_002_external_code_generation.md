# Bug Pattern 002: External Code Generation Without Repo Access

## Pattern Name
**"External Knowledge Gap" Anti-Pattern**

## Classification
- **Category:** Code Generation / AI Collaboration
- **Severity:** CRITICAL
- **Frequency:** Very Common (19 instances in 2 sessions)
- **Detection Difficulty:** Medium (imports fail at runtime, not always caught by IDE)

## Symptoms
- `ImportError: No module named 'memory.packet_envelope'`
- `AttributeError: 'PacketEnvelope' has no attribute 'from_dict'`
- Pre-commit hooks reject code (print statements, missing DORA headers)
- Tests fail with "fixture not found" errors
- Hardcoded values differ from actual config

## Root Cause
AI agents (Perplexity, ChatGPT, Claude web UI) generate code based on:
1. **Generic Python knowledge** (not L9-specific)
2. **Inferred patterns** (guess module structure)
3. **Outdated training data** (API signatures changed)

They **lack real-time repo access** via MCP, so they hallucinate imports, function signatures, and file paths.

## Real-World Examples

### Example 1: Wrong Import Path (Chaos Guide)
```python
# WRONG — Generated by Perplexity
from memory.packet_envelope import PacketEnvelope

# CORRECT — Actual L9 path
from core.schemas.packet_envelope_v2 import PacketEnvelope
```

**Impact:** All 4 test files failed to import

### Example 2: Wrong API Signature (Chaos Guide)

```python
# WRONG — Generated assumption
packet = PacketEnvelope.from_dict({"id": "test"})

# CORRECT — Actual L9 API (Pydantic model)
packet = PacketEnvelope(id="test", content=...)
```

**Impact:** Tests crashed at runtime with `AttributeError`

### Example 3: Non-Existent Module (Chaos Guide)

```python
# WRONG — Generated assumption
from api.health import get_system_health

# REALITY
# No such module — health routes are in api/server.py
```

**Impact:** Declarative chaos runner completely broken

### Example 4: Config Drift (3 Manual Bug Fixes)

```python
# WRONG — mcp_server.py
def search_memory(project_id: str = "l9"):

# WRONG — main.py
context = build_context(project_id="l9-default")

# CORRECT — Both should use
from core.config_constants import DEFAULT_PROJECT_ID
```

**Impact:** 403 errors on all searches

## Detection Strategy

### Automated (Preferred)

```bash

make validate-external-code FILE=chaos_guide.md
```

### Manual (Quick Check)

```bash
# Test all imports resolve
python -c "from memory.packet_envelope import PacketEnvelope"
# ImportError = code is broken

# Check function exists
python -c "from memory.ingestion import ingest_packet; print(ingest_packet.__doc__)"
```

## Prevention

### Solution 1: MCP-Enabled Code Generation

Always use AI agents with MCP access to L9 repo:

- Cursor with L9 workspace rules (has file access)
- Claude Desktop with MCP servers
- Perplexity Spaces with GitHub MCP

Agents without repo access (ChatGPT web, Perplexity web) should only be used for **concepts and ideas**, never for copy-paste code.

### Solution 2: Validation Pipeline

Workflow for external code:

1. Generate code (ChatGPT, Perplexity, etc.)
2. **STOP** — do not commit yet
3. Run validator: `make validate-external-code FILE=guide.md`
4. Fix all critical issues
5. Then commit

### Solution 3: Import Resolution CI Check

Already enforced via `tests/test_imports.py` and `python -m compileall` in CI.

## Fix Checklist

- [ ] Run `make validate-external-code` on all generated files
- [ ] Fix import paths to match actual repo structure
- [ ] Update function calls to match actual signatures
- [ ] Replace print() with structlog
- [ ] Add DORA metadata headers
- [ ] Seed all random number generators
- [ ] Use config constants instead of hardcoded values
- [ ] Test locally before committing
