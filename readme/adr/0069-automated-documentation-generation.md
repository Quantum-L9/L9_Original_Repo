# ADR 0069: Automated Documentation Generation System

## Status

Accepted

## Date

2026-01-25

## Context

L9 is a large codebase with 100+ README files, 200+ Python modules, and complex interdependencies. Manual documentation maintenance doesn't scale:

- README files become stale as code evolves
- AI assistants waste tokens searching for module purposes
- Architecture reports require manual updates after refactoring
- No single source of truth for codebase structure

## Decision

Implement a three-tier automated documentation generation system using AST parsing:

### Tier 1: `reports/repo-index/` — Raw Indexes (35+ files)

Machine-generated indexes for fast lookup. Generated by `tools/export_repo_indexes.py`.

| Index                     | Purpose                        |
| ------------------------- | ------------------------------ |
| `readme_manifest.txt`     | All READMEs with descriptions  |
| `class_definitions.txt`   | All classes with file paths    |
| `function_signatures.txt` | All 4,794+ functions           |
| `route_handlers.txt`      | 180+ API routes                |
| `inheritance_graph.txt`   | 800+ inheritance relationships |
| `method_catalog.txt`      | 5,200+ class methods           |
| `pydantic_models.txt`     | 470+ BaseModel schemas         |
| `async_function_map.txt`  | 2,600+ async functions         |
| `adr_catalog.txt`         | All ADRs with DO NOT rules     |

### Tier 2: `reports/architecture/` — Architecture Artifacts (20+ files)

AST-scanned architecture reports. Generated by `tools/architecture_reports/`.

| Report                       | Contents                         |
| ---------------------------- | -------------------------------- |
| `api_route_inventory.txt`    | Route → handler → file matrix    |
| `tools_inventory.txt`        | Tool definitions and risk levels |
| `worker_inventory.txt`       | Background worker modules        |
| `memory_integration_map.txt` | Memory layer dependencies        |
| `governance_invariants.txt`  | Protected surfaces checklist     |

### Tier 3: `reports/*_superpack.md` — Curated Superpacks (6 files)

AI-friendly markdown combining raw data with context. Generated by `tools/superpack_reports/`.

| Superpack                    | Purpose                        |
| ---------------------------- | ------------------------------ |
| `governance_superpack.md`    | Authority model, policy gates  |
| `core_memory_superpack.md`   | Memory architecture deep dive  |
| `api_clients_superpack.md`   | API routes and client patterns |
| `orchestration_superpack.md` | Workers and task routing       |
| `tools_superpack.md`         | Tool registry and capabilities |
| `superpack_index.md`         | Cross-links all superpacks     |

## Rationale

1. **AST Parsing > Manual Updates**: Python's `ast` module extracts accurate class/function definitions without executing code
2. **Tiered Organization**: Raw data (indexes) → processed data (architecture) → curated docs (superpacks)
3. **AI Optimization**: Indexes are grep-friendly; superpacks are context-dense for LLM loading
4. **Single Command**: `/index` regenerates all tiers in one pass

## Consequences

### Positive

- Documentation stays current with code changes
- AI assistants can find any class/function in O(1) grep
- README manifest provides instant module discovery
- Superpacks reduce LLM context-loading by 70%

### Negative

- Requires periodic regeneration (`make indexes` or `/index`)
- AST parsing doesn't capture runtime behavior
- Large index files (function_signatures.txt is 400KB+)

## Implementation

### Generator Scripts

```
tools/
├── export_repo_indexes.py      # Tier 1: Raw indexes
├── architecture_reports/       # Tier 2: Architecture artifacts
│   ├── main.py
│   ├── route_handlers_report.py
│   └── ...
└── superpack_reports/          # Tier 3: Curated superpacks
    ├── main.py
    ├── governance_report.py
    └── ...
```

### Output Structure

```
reports/
├── repo-index/                 # Tier 1: 35+ .txt indexes
│   ├── readme_manifest.txt
│   ├── class_definitions.txt
│   ├── function_signatures.txt
│   └── ...
├── architecture/               # Tier 2: 20+ .txt artifacts
│   ├── api_route_inventory.txt
│   ├── tools_inventory.txt
│   └── ...
├── *_superpack.md              # Tier 3: 6 curated superpacks
└── superpack_index.md
```

### Regeneration Commands

```bash
# All tiers
python tools/export_repo_indexes.py
python -m tools.architecture_reports.main
python -m tools.superpack_reports.main

# Or via slash command
/index
```

## DO NOT Rules

1. **DO NOT** manually edit files in `reports/repo-index/` — they are auto-generated
2. **DO NOT** manually edit files in `reports/architecture/` — regenerate instead
3. **DO NOT** add new index types without updating `/index` command docs
4. **DO NOT** store secrets or credentials in any reports/ file
